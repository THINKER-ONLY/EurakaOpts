## 实际改动

仅调整通用的 shape-based split 选择与相应常量。`flashattn`、`_get_kernel`、`run_kernel`、`_usable_block_h` 的整个函数 AST 均与已过 OJ 的版本相同；生产模块仍只导入 tilelang 与 tilelang.language。

- context < 2048 保留不分片。
- 短 context ≤ 4096 或基础网格已有多个 CTA 时，目标为 128 个 CTA；较长 context 且基础网格只有一个 CTA 时，目标为 64 个 CTA。
- 根据 batch 和 head tile 计算 split 数，最多 128，每片至少 32 个 key；FP16 partial-output 元素预算保持 8388608（16 MiB）。
- 移除旧版 batch > 8 禁止 split 的限制；128 线程、N=32、零级流水线、FP32 LSE 与稳定合并保持不变。
- 所有全局赋值 RHS 通过 ast.literal_eval，保留此前 OJ 字面量兼容修复；7200 组纯 Python 调度边界检查通过。

这些选择仅依赖张量形状和资源预算，不查询输入数据、不给测试点编号做分支，也不缓存参考输出。

## 方法与证据边界

- GPU：MetaX C500，当前实例 50% compute 切片，设备报告 104 个 SM、每块/每 SM 65536 B 共享内存。
- 先对 71.5 分模块的显式 flashattn 参数做单种子配置扫描，再生成候选，随后对候选跑完整 31 组、两个种子验收。
- 数值参考使用原始测试文件的 ref_program，容差保持 rtol=2e-4、atol=1e-4、max_mismatched_ratio=0.01；输出预填 NaN，并独立要求输出有限。
- 最终性能对照是 71.5 分模块 ff56144e...，不是最早的未优化实现。测试桥接器原样调用其 _get_kernel；为兼容既有验收适配器的返回输出接口，桥接器每次分配 output，而候选使用传入的预分配 output。该接口差异保留在源码中可审阅，未将桥接器误标为生产算子。
- 原始验收适配器里 baseline_launch 的 out_idx=[4] 描述四输入/返回输出接口；本轮实际执行的是上述桥接器，不是给生产算子新增 out_idx 装饰器。参考程序未改写。
- 预热 5 次，用同步 CUDA events 计量 5 批、每批 20 次的每调用平均值，再取批次中位数；编译、输入及参考计算均在计时区间外。
- 两实现每组均通过两个种子，31 组均有有效配对计时。没有明显实测回退；约 1.000× 的差异仅按基本持平解释。
- N=64 实验需要 92160/96256 B 共享内存，实际 launch 失败，未纳入候选或性能汇总，也未修改设备/编译器资源上限。
- 用户只提供 OJ #1 的完整配置；其余五项与本地前六组的对应仍为截图与已有用例推断。测试覆盖所有原始 31 组，不依赖这一推断才能正确计算。
- 本轮没有重跑或修复先前四组附加短序列严格容差失败；验收覆盖限定为这里的原始 31 组。
