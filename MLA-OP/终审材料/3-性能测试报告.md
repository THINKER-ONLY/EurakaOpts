本报告给出 MLA Decode 内核在赛题 6 个计分 case 上的性能测量结果与分析。

## 2. 测试集合与参数设置

测试集合即赛题的 6 个计分 case，形状为 batch=1、heads=16、kv_heads=1、dim=512、pe_dim=64、fp16，kv_ctx 取 2048 至 65536。

计时参数：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| 预热次数 | 20 | 排除首次编译与冷缓存 |
| 每轮迭代 | 50 | 单轮内连续启动 50 次 |
| 采样轮数 | 5 | 每轮单独计时 |
| 统计量 | 中位数 | 取 5 轮中位数，抑制离群值 |
| 计时工具 | CUDA event | `torch.profiler` 在本栈上数据不可信 |

计时覆盖一次完整的内核启动，包含启动开销。

## 5. 结果分析

### 5.1 成本模型

内核耗时可按两种方式分解：

```text
time = 固定成本 + 每 tile 成本 × 每个 CTA 的 tile 数
```

把循环强制写成 0 次与 1 次，可以直接测出这两项。

在 ctx=16384 上，循环 0 次时为 13.20 微秒，1 次时为 16.14 微秒，完整运行为 35 微秒。由此得到：第一个 tile 成本 2.94 微秒，其后的 tile 每个 4.79 微秒。

第一个 tile 更便宜，是因为它的一部分访存与内核启动后的准备工作重叠。

### 5.2 固定成本的构成

13.20 微秒的固定成本逐项实测如下：

| 项目 | 微秒 | 说明 |
| --- | ---: | --- |
| 启动 | 2.90 | 空内核的设备时间，无法消除 |
| 首个 tile 的 KV 与 K_pe 拷贝 | 2.28 | 唯一没有预取掩护的传输 |
| Q 与 Q_pe 拷贝 | 1.03 | 命中 L2 |
| 输出转置暂存 | 2.02 | 等待最后一次 MMA 提交 |
| 局部结果写回 | 0.82 | 1.7 MB |
| 到达自旋 | 1.23 | 等待全部 CTA 到齐 |
| 归并与最终写出 | 2.48 | 读回 1.7 MB 并加权求和 |

这些项目之和与实测值吻合，差额来自相互重叠的部分。

短上下文没有循环可摊，固定成本就是全部，因此 2048 档的耗时几乎等于固定成本。

### 5.3 显存带宽随传输规模变化

本机实测的有效带宽强烈依赖传输规模：

| 传输规模 | 有效带宽 |
| ---: | ---: |
| 4 MB | 209 GB/s |
| 8 MB | 358 GB/s |
| 64 MB | 1,059 GB/s |
| 256 MB | 1,373 GB/s |

这解释了 3 节中带宽随 kv_ctx 上升的现象：2048 档只需搬运 2.3 MB，设备无法进入高带宽区间；65536 档搬运 75 MB，才接近峰值。

短上下文的性能因此不只取决于内核本身，还受这一硬件特性约束。

### 5.4 逐 case 分析

**2048。** 64 个 CTA 各处理 1 个 tile，耗时由固定成本主导。启动 2.90 微秒、局部结果往返约 3.9 微秒，两项合计已占 15.52 微秒的近一半。该档进一步提升的空间被这两项封住。

**4096 与 8192。** 每个 CTA 分别处理 2 个与 3 个 tile。这两档在本轮改为走长上下文的快速路径（每 tile 3 个 barrier、预取拆两组、512 线程），4096 从 19.70 微秒降到 17.22，8192 从 29.03 微秒降到 24.24。

**16384。** 每个 CTA 处理 5 个 tile。该档已到访存上限：18.9 MB 的必需流量在 31 微秒内搬完，有效带宽约 610 GB/s。一个对照实验确认了这一点——把 QK 的 K 维跨两个 warp 组拆分、每 tile 的 MMA 工作量减半，本地快 1.35 微秒，判题机读数不变；同一改动在 32768 与 65536 上却如实变慢。这说明该档的瓶颈在访存，不在算力。

**32768 与 65536。** 每个 CTA 分别处理 10 个与 20 个 tile，固定成本被 tile 数摊薄，耗时接近流式拷贝的极限。两档均已达到 99 分。

### 5.5 本机与判题机的差异

本机 C500 是 50% 带宽切片，绝对耗时比判题机高 1 至 2 微秒。

因此本机按官方基线折算的 display 为 97.83，判题机为 98.17。

两者的差异主要来自带宽：本机测出的内存侧收益会被放大，在判题机上不一定成立。本报告中的所有结论均以判题机为准，本机数据仅用于版本之间的横向比较。

## 6. 结论

1. 6 个计分 case 的判题耗时为 0.012 至 0.088 毫秒，全部达到 97 分以上，其中两档为 99 分。
2. 短上下文的瓶颈是固定成本，其中启动与局部结果往返合计约 6.8 微秒，无法通过调参消除。
3. 长上下文的瓶颈是显存带宽，本机的有效带宽受传输规模限制，短上下文无法进入高带宽区间。
4. 16384 档已到访存上限，剩余的 1 微秒需要减少字节数或提高有效带宽，两者均已触及上限。
