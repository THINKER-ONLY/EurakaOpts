**ROOT_CAUSE**

v151 replaces the E64 FC2 high-level batched matmul path with a custom grouped TileLang kernel. The diff adds `_grouped_e64_fc2_kernel` and dispatches it only when `num_experts == 64`.

That custom kernel cannot compete on this shape. The old path uses high-level BMM over expert chunks, letting the backend choose a mature GEMM implementation for the large dense FC2 workload. v151 instead decomposes E64 FC2 into many smaller expert/block tiles with explicit shared-memory staging, per-block row guards, manual weight loads, and scalar weighted stores. For `experts=64, hidden=7168, intermediate=2048, total_tokens=9088`, the FC2 workload is large enough that library/BMM efficiency dominates; the custom grouped kernel loses tensor-core utilization, launch/work partition efficiency, and memory scheduling quality.

The result is not a small tile miss. A `+119.8%` case3 regression means this operator family is structurally worse for the target shape.

**FAMILY_STATUS**

Reject / retire the v151 grouped E64 FC2 family.

Do not continue tuning `block_token`, `block_dexpert`, `block_dhidden`, stages, or thread count inside this kernel family. The experiment answered the main question: custom grouped FC2 is the wrong abstraction for E64 here.

**BASELINE_DECISION**

Keep v149 as the active baseline.

**NEXT_DIRECTION**

Move to a materially different operator-dispatch direction: preserve high-level BMM for FC2 and look for dispatch-level restructuring around when to use packed chunked BMM versus specialized paths.

Recommended next branch:
- Keep E64 FC2 on high-level chunked BMM.
- Explore shape-specific dispatch for FC1/SwiGLU/packing/unpacking instead of replacing FC2 GEMM.
- Target reducing launches, workspace movement, or redundant elementwise passes around BMM.
- Consider E64-specific chunk scheduling or output-weight fusion around the BMM result, but not a hand-written grouped FC2 GEMM.

**FINAL_VERDICT**

v151 is a clean negative result. It proves the official-style grouped FC2 custom kernel is not competitive for E64. Revert to v149 as baseline and redirect effort away from FC2 tile tuning toward dispatch restructuring that keeps backend BMM on the large dense matmul.
