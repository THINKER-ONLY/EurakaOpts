ALIAS_LIFETIME_PROOF

Safe in intended stream order:

`out-as-packed_input` is written by pack, then read by `up_output = packed_input @ up_w.T` and `gate_output = packed_input @ gate_w.T`. After both FC1 matmuls finish, `packed_input` has no later reads. FC2 writes final rows into `out` only after activation is produced. PyTorch/TileLang launches on the same stream preserve this order.

VALID_OUTPUT_OVERWRITE_PROOF

Valid rows are safe because `out` has no valid final contents before FC2. Pack may overwrite arbitrary prefix rows, including rows that correspond to final output positions. Later unpack writes every valid output row:

```text
out[group_padded_offsets[e] + i, :] for i < group_sizes[e]
```

Thus contaminated valid rows are fully overwritten by FC2 unpack.

PADDING_RESTORE_KERNEL

Required. v160 relies on untouched padded rows staying zero; out-as-pack breaks that.

Kernel behavior:

```text
for each expert e:
  start = group_padded_offsets[e]
  end = group_padded_offsets[e + 1]
  valid_end = start + group_sizes[e]
  zero out[valid_end:end, :]
```

This zeros exactly physical padding rows and leaves valid rows untouched.

MEMORY_SAVINGS

E16 packed workspace removed:

16 * 192 * 2048 * 2 bytes = 12,582,912 bytes ~= 12.0 MiB
```

No activation storage is removed beyond v160’s existing `up_output` reuse. E32/E64 unchanged.

Below gate. Expected case1 timed gain: likely `0%` to `1%`, with upside from allocator pressure only. The explicit new zero-padding kernel also adds launch overhead and writes padding rows, offsetting any allocator benefit.

After both FC1 matmuls finish, `packed_input` has no later reads. FC2 writes final rows into `out` only after activation is produced. PyTorch/TileLang launches on the same stream preserve this order.

VALID_OUTPUT_OVERWRITE_PROOF

Valid rows are safe because `out` has no valid final contents before FC2. Pack may overwrite arbitrary prefix rows, including rows that correspond to final output positions. Later unpack writes every valid output row:

```text
out[group_padded_offsets[e] + i, :] for i < group_sizes[e]
```

Thus contaminated valid rows are fully overwritten by FC2 unpack.

PADDING_RESTORE_KERNEL

Required. v160 relies on untouched padded rows staying zero; out-as-pack breaks that.

Kernel behavior:

```text
for each expert e:
  start = group_padded_offsets[e]
  end = group_padded_offsets[e + 1]
  valid_end = start + group_sizes[e]
  zero out[valid_end:end, :]
```

This zeros exactly physical padding rows and leaves valid rows untouched.

MEMORY_SAVINGS

E16 packed workspace removed:

```text
16 * 192 * 2048 * 2 bytes = 12,582,912 bytes ~= 12.0 MiB
```

No activation storage is removed beyond v160’s existing `up_output` reuse. E32/E64 unchanged.

EXPECTED_GAIN

Below gate. Expected case1 timed gain: likely `0%` to `1%`, with upside from allocator pressure only. The explicit new zero-padding kernel also adds launch overhead and writes padding rows, offsetting any allocator benefit.

CORRECTNESS_RISKS

Main risks:

- TileLang/PyTorch alias behavior between an `out` view used as matmul input and later `out` writes should be okay by lifetime, but is not previously tested in this code.
- Must not use this path without `out.shape[0] >= 16*192`.
- Must restore padding after FC2, not before.
- Pack kernel currently does not write `i >= group_size`; that is fine for matmul only if those rows are not unpacked, but padding restoration remains mandatory because prefix contamination can overlap physical padding rows.

IMPLEMENTATION_INSTRUCTIONS

Do not implement as v162 under the requested gate. If forcing an experiment later, make it E16-only behind the static metadata guard and fall back to v160 workspace otherwise. Keep E32/E64 unchanged.
